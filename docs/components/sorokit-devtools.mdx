---
title: "SorokitDevtools"
description: "A development-only panel logging contract send activity and the TanStack Query cache"
---

A development-only devtools panel for Sorokit. Renders nothing when `process.env.NODE_ENV !== "development"`, matching `@tanstack/react-query-devtools`'s own convention, so it is always safe to leave mounted in an app.

```tsx
import { SorokitDevtools } from "@sorokit/devtools";
```

## Props

| Name          | Type      | Required | Description                                             |
| ------------- | --------- | -------- | ------------------------------------------------------- |
| `initialOpen` | `boolean` | No       | Renders the panel open by default instead of collapsed. |

## Example

```tsx
import { SorokitDevtools } from "@sorokit/devtools";

export function App({ children }: { children: React.ReactNode }) {
  return (
    <>
      {children}
      <SorokitDevtools />
    </>
  );
}
```

## Theming

The panel is built with shadcn/ui components. If your app already uses shadcn, the panel picks up your theme automatically, no setup needed. If not, it falls back to shadcn's default look.

## What it shows

A floating toggle opens a panel with two tabs:

- Sends: every [`useContractSend`](/hooks/use-contract-send) invocation this session, its current status, and, once available, its decoded args and result. For each send, a readable summary of the built transaction (operation type, source account, and simulated minimum resource fee) is shown alongside a button to copy its raw XDR, rather than a full XDR tree decode.
- Query cache: the app's TanStack Query cache, via an embedded `@tanstack/react-query-devtools` panel. Sorokit's own hooks namespace every query key under `"sorokit"`, so they're easy to pick out from your app's own queries in the same view.

<Tip>
  The send log is powered by `@sorokit/core`'s `devtoolsSendLog` store, which `useContractSend`
  writes to regardless of whether `@sorokit/devtools` is installed. Installing this package only
  adds the panel that reads from it; it never needs to be a dependency of `@sorokit/contract`.
</Tip>
