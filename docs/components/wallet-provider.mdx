---
title: "WalletProvider"
description: "The low-level wallet context primitive SoroformProvider mounts for you"
---

Wraps a subtree in a wallet connection context, driven by whichever `WalletAdapter` is passed as `adapter`. This is the primitive [`SoroformProvider`](/components/soroform-provider)'s `wallet` prop renders internally — **most apps should use that instead of rendering `WalletProvider` directly.**

```tsx
import { WalletProvider } from "@soroform/wallet-adapter";
```

## Props

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `adapter` | `WalletAdapter` | Yes | The wallet adapter to drive. |
| `networkPassphrase` | `string` | Yes | The network passphrase to initialize (and re-initialize) the adapter with. |

<Warning>
  Construct the adapter once and pass the same reference every render, same as `SoroformProvider`'s `wallet` prop — see its docs for why.
</Warning>

## When to reach for this directly

`SoroformProvider`'s `wallet` prop covers the vast majority of apps: pass it a `WalletConnector` (`stellarWalletsKit()`, `blux()`, `para()`, or your own) and it handles mounting `WalletProvider` — with the resolved network passphrase already threaded through — for you.

Render `WalletProvider` yourself only if you're doing something `SoroformProvider` doesn't anticipate — for example, driving a `WalletAdapter` you're constructing outside the `WalletConnector` shape, or unit-testing an adapter in isolation without pulling in `@soroform/provider` at all:

```tsx
import { WalletProvider } from "@soroform/wallet-adapter";

<WalletProvider adapter={myAdapter} networkPassphrase="Test SDF Network ; September 2015">
  {children}
</WalletProvider>;
```

See [`SoroformProvider`](/components/soroform-provider#wallet-connectors) for the connectors Soroform ships and how to write your own, [`useWallet`](/hooks/use-wallet) for reading connection state, and [`ConnectWalletButton`](/components/connect-wallet-button) for a ready-made connect button.
