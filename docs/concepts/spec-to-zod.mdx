---
title: "How the spec-to-Zod pipeline works"
description: "How Soroform turns a contract's spec into Zod schemas, entirely at runtime"
---

Soroform has no code generation step. Every contract-facing hook derives its validation and types from the contract's own spec, fetched at runtime from just a `contractId`.

## The pipeline

<Steps>
  <Step title="Fetch the spec">
    The first time a hook is called for a given `contractId`, Soroform calls `contract.Client.from({ contractId, rpcUrl, networkPassphrase })`. This single call handles Wasm-hash lookup, Wasm download, and the built-in spec for Stellar Asset Contracts, whichever applies to that contract. The result is cached in the TanStack Query cache under `queryKeys.contractSpec(networkPassphrase, contractId)`, with an infinite `staleTime`: a deployed contract's spec cannot change without deploying under a new contract ID.
  </Step>
  <Step title="Generate schemas">
    `generateContractSchemas(spec)` iterates every function in `spec.funcs()` and builds a Zod object schema for its arguments, via `sorobanTypeToZod`. This runs once per `Spec` instance; the result is cached in a `WeakMap` keyed by the spec object itself, so calling it again for the same spec (which every render of every hook does) is free.
  </Step>
  <Step title="Validate and call">
    `useContractCall` and `useContractSend` parse the caller's args against the generated schema before ever reaching the network. A validation failure throws synchronously, with no RPC call made.
  </Step>
</Steps>

## Type mapping

`sorobanTypeToZod` maps every one of the 26 variants `xdr.ScSpecTypeDef` can be to a Zod schema whose shape matches exactly what `Spec.nativeToScVal` expects, verified against the SDK's actual encode and decode implementation rather than assumed from its type declarations. Coverage is total, not best-effort: there is no Soroban type a contract's spec can declare that falls through to an unvalidated passthrough.

| Soroban type                                 | Zod schema                                                   | Notes                                                                                                                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `u32`, `i32`                                 | `z.number()`                                                 |                                                                                                                                                                                              |
| `u64`, `i64`, `u128`, `i128`, `u256`, `i256` | `z.bigint()`                                                 | JS numbers lose precision above 2^53; Soroban amounts routinely exceed it.                                                                                                                   |
| `timepoint`, `duration`                      | `z.bigint()`                                                 | Both are u64-valued.                                                                                                                                                                         |
| `bool`                                       | `z.boolean()`                                                |                                                                                                                                                                                              |
| `void`                                       | `z.void()`                                                   |                                                                                                                                                                                              |
| `symbol`, `string`                           | `z.string()`                                                 |                                                                                                                                                                                              |
| `bytes`                                      | `z.instanceof(Uint8Array)`                                   |                                                                                                                                                                                              |
| `bytesN`                                     | `z.instanceof(Uint8Array)` with a length refinement          |                                                                                                                                                                                              |
| `address`                                    | `z.string()` with a StrKey refinement                        | Validated with `StrKey.isValidEd25519PublicKey` / `StrKey.isValidContract`, not a hand-rolled regex.                                                                                         |
| `muxedAddress`                               | `z.string()` with a StrKey refinement                        | Also accepts `StrKey.isValidMed25519PublicKey` (`M...`), on top of the plain `address` checks.                                                                                               |
| `vec<T>`                                     | `z.array(sorobanTypeToZod(T))`                               |                                                                                                                                                                                              |
| `map<K, V>`                                  | `z.map(sorobanTypeToZod(K), sorobanTypeToZod(V))`            | A JS `Map`, not `z.record()`: Soroban map keys are not restricted to strings the way `z.record()`'s keys are.                                                                                |
| `option<T>`                                  | `sorobanTypeToZod(T).optional().nullable()`                  | The SDK's encoder treats both `null` and `undefined` as absent.                                                                                                                              |
| `result<Ok, Err>`                            | `z.union([z.object({ ok: ... }), z.object({ error: ... })])` |                                                                                                                                                                                              |
| `tuple<T1, T2, ...>`                         | `z.tuple([...])`                                             |                                                                                                                                                                                              |
| `struct` (named fields)                      | `z.object({...})`                                            |                                                                                                                                                                                              |
| `struct` (tuple struct)                      | `z.tuple([...])`                                             | Detected when every field is named `"0"`, `"1"`, `"2"`, ...                                                                                                                                  |
| `union` (data-carrying enum)                 | `z.discriminatedUnion("tag", [...])`                         | Shape is `{ tag: string, values: [...] }`; `values` is always an array, even for a single-value case.                                                                                        |
| `enum` (unit-variant enum)                   | a union of `z.literal(value)`                                | See below.                                                                                                                                                                                   |
| `val`, `error`                               | `z.unknown()`                                                | Generic placeholder markers in the spec format itself (an unresolved type parameter, or "any contract error"), not concrete Soroban value types; there is nothing more specific to validate. |

<Warning>
  A plain (unit-variant) Soroban enum's native JS value is its raw numeric case value, not its case
  name. `Spec.nativeToEnum` and `Spec.enumToNative` in the SDK both operate purely on the numeric
  discriminant. `sorobanTypeToZod` matches this: a case named `Active` with value `0` validates
  against `0`, not `"Active"`. The case names are folded into the schema's `.describe()` for editor
  tooltips only.
</Warning>

## Validation errors

A failed `.parse()` against the generated schema is caught and re-thrown as a normal Soroform error, not a bare `ZodError` escaping the hook and not a stringified blob either:

```ts
interface SoroformError {
  kind: "validation-failed";
  message: string; // z.prettifyError(zodError) — the readable, multi-line format
  cause: z.ZodError; // the original ZodError, completely untouched
}
```

`cause` is the real `ZodError`, so `error.cause.issues`, `error.cause.flatten()`, and every other Zod API stay available exactly as they would from a direct `schema.parse()` call. Soroform normalizes the `kind` and `message` for consistency with every other error it surfaces (see [Error handling](/concepts/error-handling)); it does not hide or reformat the underlying Zod error data.

```tsx
const { error } = useContractCall({ contractId, method: "transfer", args });

if (error?.kind === "validation-failed") {
  const zodError = error.cause; // z.ZodError
  console.log(zodError.flatten().fieldErrors);
}
```

## Calling it directly

`sorobanTypeToZod` and `generateContractSchemas` are plain functions with no React dependency, so you can use them outside a hook, for example to validate data before ever rendering a form:

```ts
import { Client } from "@stellar/stellar-sdk/contract";
import { generateContractSchemas } from "@soroform/contract";

const client = await Client.from({
  contractId: "CCJZ5DGASBWQXR5MPFCJXMBI333XE5U3FSJTNQU7RIKE3P5GN2K2WYD5",
  rpcUrl: "https://soroban-testnet.stellar.org",
  networkPassphrase: "Test SDF Network ; September 2015",
});

const schemas = generateContractSchemas(client.spec);
const result = schemas.transfer?.argsSchema.safeParse({
  to: "GABC...",
  amount: 100n,
});
```
