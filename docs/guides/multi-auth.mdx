---
title: "Handling multi-signature/multi-auth contract calls"
description: "Collecting signatures from multiple accounts for a single contract call"
---

`useContractWrite` covers the common case: one signer, who is also the transaction's source account, signs and sends in one step. Soroban also supports calls that need authorization from accounts other than the one invoking the transaction, for example an atomic swap where both parties must authorize their side. That needs the lower-level `AssembledTransaction` API directly.

## The shape of the problem

Say Alice invokes a `swap` call that also needs Bob's authorization. Alice's browser builds and simulates the call; Bob is not there to sign anything yet. The transaction needs to travel from Alice's machine to Bob's, get Bob's auth entry signed, travel back, and only then get sent.

## Building the initial transaction

Use `fetchContractSpec` (the same runtime spec-fetching Soroform's own hooks use) to get a `Spec`, then build with `AssembledTransaction.build` directly instead of going through `useContractWrite`, since the built-in hook only expects one signer.

```ts
import { AssembledTransaction } from "@stellar/stellar-sdk/contract";
import { fetchContractSpec } from "@soroform/contract";

const spec = await fetchContractSpec(contractId, config, queryClient);
const args = spec.funcArgsToScVals("swap", {
  a: alice.address,
  b: bob.address,
  token_a: tokenA,
  token_b: tokenB,
  amount_a: 10_0000000n,
  amount_b: 5_0000000n,
});

const tx = await AssembledTransaction.build({
  contractId,
  networkPassphrase: config.networkPassphrase,
  rpcUrl: config.rpcUrl,
  publicKey: alice.address,
  method: "swap",
  args,
  parseResultXdr: (xdr) => spec.funcResToNative("swap", xdr),
  signTransaction: alice.signTransaction,
  signAuthEntry: alice.signAuthEntry,
});
```

## Checking who else needs to sign

```ts
const whoElseNeedsToSign = tx.needsNonInvokerSigningBy();
// ["GBOB..."]
```

## Handing off to the other signer

Serialize the transaction, send it to Bob's machine by whatever channel your app uses (your backend, a WebSocket, anything that can carry a string), and reconstruct it there:

```ts
// On Alice's machine
const json = tx.toJson();
```

```ts
// On Bob's machine, after receiving `json`
import { AssembledTransaction } from "@stellar/stellar-sdk/contract";

const restored = AssembledTransaction.fromJson(
  {
    contractId,
    networkPassphrase: config.networkPassphrase,
    rpcUrl: config.rpcUrl,
    parseResultXdr: (xdr) => spec.funcResToNative("swap", xdr),
  },
  JSON.parse(json),
);

await restored.signAuthEntries({ signAuthEntry: bob.signAuthEntry });

const json2 = restored.toJson();
// send json2 back to Alice
```

## Finishing on the original signer's machine

```ts
// Back on Alice's machine, after receiving `json2`
const final = AssembledTransaction.fromJson(
  {
    contractId,
    networkPassphrase: config.networkPassphrase,
    rpcUrl: config.rpcUrl,
    parseResultXdr: (xdr) => spec.funcResToNative("swap", xdr),
  },
  JSON.parse(json2),
);

const sentTx = await final.signAndSend({ signTransaction: alice.signTransaction });
```

<Note>
  `signAuthEntries` and `signAndSend` both accept `signAuthEntry` / `signTransaction` directly, matching `useWallet()`'s `signTransaction` and `signAuthEntry` fields, so they can be passed straight through the same way `useContractWrite` does internally.
</Note>

<Warning>
  Sending to all of `needsNonInvokerSigningBy`'s owners in parallel is not supported; hand the transaction off to one signer at a time.
</Warning>
