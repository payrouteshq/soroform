---
title: "useContractCall"
description: "Simulate a read-only contract method call and get its decoded result"
---

Simulates a read-only contract method call and returns its decoded result as a TanStack Query result. Requires no connected wallet: reads are simulation-only.

```ts
import { useContractCall } from "@sorokit/contract";

function useContractCall<TResult = unknown>(
  options: UseContractCallOptions,
): UseQueryResult<TResult>;
```

## Parameters

| Name         | Type                      | Required | Description                                               |
| ------------ | ------------------------- | -------- | --------------------------------------------------------- |
| `contractId` | `string`                  | Yes      | The deployed contract's address (`C...`).                 |
| `method`     | `string`                  | Yes      | The read-only method to call.                             |
| `args`       | `Record<string, unknown>` | No       | Named arguments for the method, keyed by parameter name.  |
| `network`    | `SorokitNetwork`          | No       | Overrides the network from the nearest `SorokitProvider`. |
| `enabled`    | `boolean`                 | No       | Whether the query should run. Defaults to `true`.         |

## Return value

Everything TanStack Query's `useQuery` returns, typed to `TResult`. The fields you'll use most:

| Field       | Type                   | Description                                                         |
| ----------- | ---------------------- | ------------------------------------------------------------------- |
| `data`      | `TResult \| undefined` | The decoded result, once loaded.                                    |
| `isLoading` | `boolean`              | Whether the initial fetch is in flight.                             |
| `error`     | `SorokitError \| null` | A normalized error; see [Error handling](/concepts/error-handling). |
| `refetch`   | `() => void`           | Manually re-runs the call.                                          |

## Example

```tsx
import { useContractCall } from "@sorokit/contract";

const CONTRACT_ID = "CCJZ5DGASBWQXR5MPFCJXMBI333XE5U3FSJTNQU7RIKE3P5GN2K2WYD5";

function Balance({ address }: { address: string }) {
  const { data, isLoading, error } = useContractCall<bigint>({
    contractId: CONTRACT_ID,
    method: "balance",
    args: { id: address },
  });

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>{error.message}</p>;
  return <p>{data?.toString()}</p>;
}
```

## Caching

The contract's spec and args schema are fetched and derived once, the first time any hook calls that `contractId`, then cached (see [How the spec-to-Zod pipeline works](/concepts/spec-to-zod)). The call itself is cached under `queryKeys.contractCall(networkPassphrase, contractId, method, args)`, so calling this hook again with the same contract, method, and args reuses the cached result per TanStack Query's usual `staleTime` rules. It is invalidated automatically by [`useContractSend`](/hooks/use-contract-send) on a successful send to the same contract.
