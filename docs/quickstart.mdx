This walks through going from a fresh React or Next.js app to a working contract call and send. There is no code generation step: every hook below works from just a `contractId`.

## Prerequisites

- A React 18+ or Next.js 15+ app
- A Soroban contract deployed on testnet (or mainnet, with your own RPC URL)
- A browser wallet extension for testing writes (Freighter, xBull, Albedo, Lobstr, Hana, or Rabet)

## Install

<CodeGroup>

```bash npm
npm install @soroform/core @soroform/provider @soroform/wallet-adapter @soroform/contract \
  @creit.tech/stellar-wallets-kit @stellar/stellar-sdk @tanstack/react-query zod react-hook-form @hookform/resolvers
```

```bash pnpm
pnpm add @soroform/core @soroform/provider @soroform/wallet-adapter @soroform/contract \
  @creit.tech/stellar-wallets-kit @stellar/stellar-sdk @tanstack/react-query zod react-hook-form @hookform/resolvers
```

</CodeGroup>

`@tanstack/react-query`, `zod`, `react-hook-form`, and `@hookform/resolvers` are peer dependencies: install them alongside Soroform so your app controls their versions. `@creit.tech/stellar-wallets-kit` is the wallet connector this quickstart uses; see [`WalletProvider`](/components/wallet-provider) for the other adapter Soroform ships (`blux()`), or for writing your own.

## Wrap your app in the providers

`SoroformProvider` resolves your network configuration and supplies a TanStack Query client to every hook. `WalletProvider` must be nested inside it, since it reads the network from `SoroformProvider`'s context, and takes a wallet adapter to drive — `stellarWalletsKit()` here.

```tsx app/providers.tsx
"use client";

import type { ReactNode } from "react";
import { SoroformProvider } from "@soroform/provider";
import { WalletProvider } from "@soroform/wallet-adapter";
import { stellarWalletsKit } from "@soroform/wallet-adapter/adapters/stellar-wallets-kit";

const adapter = stellarWalletsKit();

export function Providers({ children }: { children: ReactNode }) {
  return (
    <SoroformProvider network="testnet">
      <WalletProvider adapter={adapter}>{children}</WalletProvider>
    </SoroformProvider>
  );
}
```

```tsx app/layout.tsx
import type { ReactNode } from "react";
import { Providers } from "./providers";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

## Read from a contract

`useContractCall` simulates a read-only method call and returns the decoded result. It needs no connected wallet, since reads are simulation-only.

```tsx app/balance.tsx
"use client";

import { useContractCall } from "@soroform/contract";

const CONTRACT_ID = "CCJZ5DGASBWQXR5MPFCJXMBI333XE5U3FSJTNQU7RIKE3P5GN2K2WYD5";

export function Balance({ address }: { address: string }) {
  const { data, isLoading, error } = useContractCall<bigint>({
    contractId: CONTRACT_ID,
    method: "balance",
    args: { id: address },
  });

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>{error.message}</p>;
  return <p>Balance: {data?.toString()}</p>;
}
```

## Write to a contract

`useContractSend` builds, simulates, signs, and sends a state-changing call. Connect a wallet first with `useWallet` or `ConnectWalletButton`.

```tsx app/transfer.tsx
"use client";

import { ConnectWalletButton } from "@soroform/wallet-adapter";
import { useContractSend } from "@soroform/contract";

const CONTRACT_ID = "CCJZ5DGASBWQXR5MPFCJXMBI333XE5U3FSJTNQU7RIKE3P5GN2K2WYD5";

export function TransferButton({ to }: { to: string }) {
  const { status, sendAsync, error } = useContractSend({
    contractId: CONTRACT_ID,
    method: "transfer",
  });

  return (
    <div>
      <ConnectWalletButton />
      <button
        disabled={status === "simulating" || status === "submitting"}
        onClick={() => sendAsync({ to, amount: 100n })}
      >
        {status === "idle" || status === "success" ? "Transfer" : status}
      </button>
      {error && <p>{error.message}</p>}
    </div>
  );
}
```

The first call for `CONTRACT_ID` fetches its spec and derives a Zod schema for the `transfer` method automatically; both are cached, so calling either hook again, or pointing them at a different `contractId`, needs no further setup.
